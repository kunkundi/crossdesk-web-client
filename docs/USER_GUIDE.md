## 快速连接

1. 在被控电脑安装并启动 [CrossDesk 桌面端](https://github.com/kunkundi/crossdesk/releases)，确认已连接服务器，并授予屏幕捕获和远程输入所需的系统权限。
2. 打开 [Web 客户端](https://web.crossdesk.cn/)，输入被控端当前显示的**远程设备 ID** 和 **6 位密码**。ID 中的空格会自动去除。
3. 等待页面完成信令连接与登录，点击“连接”或按 Enter。按钮启用需要同时满足：信令就绪、ID 非空、密码长度为 6。
4. 出现远程画面后开始操作；结束时展开浮动控制栏，点击“断开连接”并确认。

当前桌面端已自动启用 SRTP；浏览器 WebRTC 要求媒体加密，使用自定义或旧被控端时需确保支持并启用。

使用自建服务器时，两端必须接入同一套信令服务。仅 Fork 或部署网页不会自动搭建服务端，也不会自动修改被控端的服务器设置。

## 操作指引

### 电脑浏览器

- 在远程画面内点击后操作鼠标和物理键盘。支持的浏览器会请求鼠标锁定，按 **Esc** 可释放鼠标，返回页面控件；行为取决于浏览器的 [Pointer Lock 支持](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API)。
- 使用鼠标左 / 中 / 右键和滚轮操作远端。键盘通过按键事件发送，部分系统或浏览器保留的快捷键可能无法传递。
- 点击 CrossDesk 悬浮图标展开或关闭菜单，拖动图标可调整位置；点击菜单外或关闭按钮可收起菜单。Esc 在子页面返回主菜单，在主菜单关闭。

### 手机和平板浏览器

**单指轻点画面是左键，双指轻点是右键；滑动用于移动鼠标。** 也可以使用虚拟鼠标按钮点击。

| 操作 | 使用方式 |
| --- | --- |
| 绝对鼠标 | 点击鼠标模式按钮，切换到“绝对鼠标”，触摸位置对应远端鼠标位置 |
| 相对鼠标 | 默认使用“相对鼠标”，在画面上滑动，以相对位移移动鼠标 |
| 左键 / 右键 | 单指轻点画面触发左键，双指轻点触发右键；也可使用虚拟鼠标的“左键” / “右键” |
| 拖动 | 按住虚拟鼠标的“左键”并滑动，松开结束拖动 |
| 滚动 | 使用虚拟鼠标的 ↑ / ↓，长按可连续滚动 |
| 输入按键 | 点击菜单“键盘”或虚拟鼠标上的 ⌨ 打开键盘，拖动标题栏调整位置，点击 × 关闭 |
| 缩放 / 平移 | 在画面上双指捏合缩放至 1–3 倍，双指移动调整视图；双击画面重置缩放 |
| 收起虚拟鼠标 | 通过悬浮菜单的“虚拟鼠标”按钮切换显示或隐藏 |

触控布局根据浏览器报告的指针和悬停能力启用，不仅取决于屏幕大小。虚拟键盘发送按键码，未提供本机输入法文本提交接口。

### 切换画面与播放音频

- **画面：** 打开菜单“显示器”，选择已收到的视频轨道。选项取决于被控端提供的画面，控制数据通道打开后才能切换。
- **音频：** 音频按钮在收到远端音频轨道前不可用。浏览器若阻止自动播放，点击音频按钮开始播放；再次点击静音。该按钮控制浏览器播放，不是被控端的系统音量开关。
- **断开：** 打开“断开连接”并确认后返回连接表单；取消则保留当前会话。信令重连与远程会话重建是不同过程；远程会话失败返回表单后，需要再次点击“连接”。

### 画面设置与网络状态

- **画面设置：** 选择低 / 中 / 高画质、30 / 60 FPS 帧率上限，以及“帧率优先”“画质优先”或“平衡”。可用选项取决于被控端上报的能力；不支持的选项禁用，提交后等待确认，失败时按界面提示重试。
- **网络状态：** 查看分辨率、帧率、视频接收速率、丢包率、往返延迟、画面缓冲和解码耗时，以及直连 / 中继路径；中继时还显示传输协议。数据受浏览器统计及当前媒体状态影响，暂不可用不等于零。
- **显示器：** 仅列出被控端提供的视频轨道，无法切换到尚未发送的显示器。

这些控件由 [session_controls.js](../session_controls.js) 提供，在 `web_client.js` 后加载；手动部署时需要一并上传。

### 文件传输

1. 展开悬浮菜单，打开“文件传输”。桌面端需包含支持 Web 文件通道的 MiniRTC；旧版会提示更新，发送按钮保持禁用。
2. 点击“选择文件并发送”，可多选文件并按队列逐个发送。进度以远端确认的字节数为准，接收完成后才显示发送成功。文件保存到桌面端设置的接收目录（默认桌面）。
3. 远端向当前 Web 会话发送文件后，自动边接收边写入浏览器默认下载目录；无需选择目录或点击保存。悬浮图标显示蓝点，在“文件传输”中查看进度。下载使用安全文件名，同名文件由浏览器处理。
4. 点击“取消”停止排队、发送或接收；点击“×”移除已结束的记录。超过 30 秒没有传输进展会失败，需重新发送。

接收不再有 **256 MiB** 上限，页面按块处理，不缓存整个文件；实际可保存大小取决于浏览器及可用磁盘空间。最多保留 100 条记录，移除记录不删除已下载文件。不支持文件夹或断点续传。

请通过 **HTTPS 或 localhost** 打开页面，并使用支持 Service Worker 的浏览器；直接双击 HTML（`file://`）不能流式接收。若浏览器开启“每次询问保存位置”，仍会询问；多文件下载可能需要允许本站下载文件。下载被拦截或取消时，请允许下载后重新发送。

**断开、重新连接或刷新页面会停止进行中的传输和下载，已完成的下载会保留。** 网页显示接收完成表示数据已交给浏览器，请在浏览器下载列表中确认最终保存结果。

### 剪贴板

在远程控制菜单中打开“剪贴板”。需要同时更新 Web 客户端和支持 Web 剪贴板同步的桌面客户端；旧版被控端会显示升级提示。

- 本机到远端：在远程画面按 Ctrl+V、Command+V 或 Shift+Insert，先发送文本，确认远端剪贴板写入成功后再转发该粘贴组合键。组合键应适合被控端系统。
- 手动发送：展开“手动传递文本”，点击“发送到远端”，再在远端应用中粘贴。也可在“发送文本”框粘贴 / 输入内容后点击“发送”。
- 远端到本机：在被控电脑复制文本后，展开“手动传递文本”，点击“复制到本机”，或选中“远端文本”框中的内容手动复制。读写权限不足时会自动展开对应文本框。
- “自动同步”在每次新连接中默认开启，可手动关闭，开关设置仅对当前连接有效。在支持持久剪贴板权限的浏览器中，授权后可在页面位于前台时自动同步。Safari、Firefox、权限拒绝或非安全页面请使用“手动传递文本”中的按钮 / 文本框；读取和写入系统剪贴板的 API 需要 HTTPS 或 localhost。

每次最多 128 KiB UTF-8 纯文本，支持中文、表情和换行；不传图片、文件、富文本、空文本或含 NUL 的文本。内容不写入浏览器持久存储，断开或重连时清除会话缓存和文本框。粘贴等待期间离开页面、点击其他位置或输入新按键会取消待执行的粘贴。Windows SYSTEM 无人值守宿主仍不开放剪贴板访问。

## 常见问题

| 现象 | 检查方式 |
| --- | --- |
| “连接”按钮灰色 | 确认信令已登录、设备 ID 非空且密码为 6 位；未填写表单时灰色是正常状态 |
| “无法连接服务器” / 一直重连 | 检查 `signalingUrl` 的协议、地址、端口、证书、服务端状态及代理的 WebSocket 支持；修复后点击“重连服务器” |
| “没有该设备” | 确认两端使用相同信令服务，被控端在线，且填写的是其当前设备 ID |
| “密码错误” | 使用被控端当前显示的 6 位密码，注意是否已刷新 |
| 连接超时 / 没有画面 | 检查被控端屏幕捕获权限与媒体加密兼容性，再检查 STUN / TURN、动态凭据及中继端口 |
| 有画面但不能操作或切换 | 检查控制数据通道是否打开，以及被控端的远程输入权限 |
| 手机上点画面没有点击效果 | 单指 / 双指短暂轻点并抬起，分别触发左键 / 右键；滑动、长按和捏合不会触发点击，也可使用虚拟鼠标按钮 |
| 没有声音 | 确认被控端提供音频轨道且有声音，再检查页面音频按钮、站点播放权限及本机音量 |
| 更新配置后仍连旧服务器 | 检查配置是否在主脚本之前加载、发布是否完成；强制刷新并检查实际下载的 HTML / JS |
| Fork 后地址或主屏幕入口不对 | 检查 Pages 的 Custom domain、`CNAME`、发布目录及 `manifest.json` 的 `start_url` |

### 排查直连失败

从创建 `RTCPeerConnection` 起，网页在内存中维护 `window.CrossDeskIceDiagnostics`，无需收到视频即可记录 ICE 状态、候选类型、IPv4 / IPv6 / mDNS、候选检查结果和 STUN / TURN 错误码。断开后保留最后一个 PeerConnection 的诊断，下一次连接时重置。在浏览器开发者工具 Console 中运行：

```js
JSON.stringify(window.CrossDeskIceDiagnostics, null, 2)
```

`first_route` 是首次采样到的路径；`route` 是当前路径；`route_at_30s` 是 PeerConnection 创建满 30 秒后的首次采样路径，提前断开的连接保持 `null`。`candidate_pairs` 可区分候选缺失、检查失败与选中了中继。诊断不包含设备 ID、候选 IP、完整 SDP 或凭据，也不会自动上传；候选与事件列表均有长度限制。它不是总体直连率统计，需要使用相同设备和网络比较多次连接。

Web 支持缓存先于 Offer / 远端描述到达的候选，并用会话标识和 `ufrag` 隔离候选。旧服务端省略这些字段时保留兼容处理，但无法完全识别同一设备旧连接的无标记消息。新版被控端还会在发出 Offer 后立即收集候选，并提供 ICE-TCP 直连候选；这些能力需要更新并重新构建桌面端及 MiniRTC。
